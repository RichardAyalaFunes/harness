# HTML design contract

Applies to readme.html, decision artifacts, and future interface prototypes. Product-specific choices may extend it once the end user is known.

- Self-contained UTF-8 HTML, inline CSS/JavaScript, no CDN, tracking, remote fonts, or network requests. Set viewport and lang. Work from a local file.
- Visual language (human decision 2026-11-08, prompts/client-context/019-user.md; supersedes `docs/ui-style-reference.md`, which stays as a historical record): light frosted-glass UI, as in `_work/2026-11-07-client-context/proto-ats-a-hifi.html`. Applies to the product UI, readme.html and new artifacts. Light theme only.
- Tokens: backdrop #eef0f3 with soft radial washes of blue #c3d9f2 (top-left) and warm yellow #f3d996 (bottom-right); glass card rgba(255,255,255,.58) with 26px backdrop blur, 1px rgba(255,255,255,.9) edge, 28px radius, shadow 0 12px 40px rgba(40,55,80,.09); inner tile rgba(255,255,255,.86), 20px radius; ink #16181d; secondary text #4b5160; muted text #6b7180; change marker yellow #f8c65a (soft #fdeec7); success #1d6b43 on #dff3e8; error #a8324a on #fbe1e6; selected state and primary buttons ink #16181d with white text. Type: geometric sans via the system stack ("Segoe UI Variable", "Segoe UI", system-ui), large numerals for key figures, 40px pill buttons, segmented tabs with a dark selected tab.
- Required adaptations: (1) no remote fonts or images. (2) Yellow is a background or marker only, always with dark text; never yellow text. (3) Do not rely on the translucent fill alone to show interactivity: selectable items need a visible control (radio, checkbox, chevron) and a border, and states differ by more than colour (icon or label). (4) Focus rings: 3px ink outline. (5) Do not reuse the reference image's brand name, logo, photos or copy; this is a fictional recruitment agency's product. Earlier artifacts keep their old styles as historical records.
- Clear hierarchy: purpose/status → summary → decisions or tasks → evidence/next step. Distinguish facts, recommendations, assumptions, and pending answers with text, not color alone.
- Responsive one/two-column grids that collapse below 720px. No fixed-width overflow. Semantic headings, fieldsets/legends, explicit labels, visible keyboard focus, adequate contrast, 44px action targets.
- Every question: stable ID, why it matters, meaningful options with benefits/costs and recommended default. Defaults are proposals; leave answer inputs blank. Add free text for edge cases.
- Prototype fidelity and scope must be labelled. Show relevant empty, failure, and success states once the workflow is known. Never present a prototype as a working integration.
- Decision forms export versioned JSON with question IDs and answers. Explain that download does not write repository files; answers become canonical only after explicit import/review by the agent. Do not insert user text via innerHTML.
- Readme and artifacts share these tokens. Changes to the visual language update this file before dependent HTML. Check layout, links, keyboard use, and export behavior before claiming visual verification.
